# Home Assistant Aqua Temp & Hi Temp Heat Pumps

This is Home Assistant's integration for PHINX Aqua Temp / HiTemp compatible heat pumps (fork of [`radical-squared/aquatemp`](https://github.com/radical-squared/aquatemp)).
It allows controlling temperature, HVAC mode (`heat`, `cool`, `auto`, `off`) and fan mode (`low`, `auto`).
It also reports all parameters available in sensors and binary sensors, including accurate online/offline (`device_status`) and availability (`unavailable` when the heat pump is powered off/offline).

AquaTemp's cloud protocol is based on [aquatemp](https://github.com/dst6se/aquatemp) project with additional functionality.

[Changelog](https://github.com/fabiobrolo/aquatemp/blob/Custom-component/CHANGELOG.md)

## How to

#### Requirements

Account for AquaTemp / HiTemp

##### Shared device to avoid token expiration when using the App parallel to Integration

Aqua Temp / Hi Temp introduced in v1.5.9 single login "feature" by default, meaning, only one device can be logged in,
Following a recommendation from [@dodg3r](https://github.com/@dodg3r) & [@kopierschnitte](https://github.com/@kopierschnitte), you can avoid it by creating additional account and sharing the device with that new account.

Requires complete deletion of integration and reinstall after restart HA

### Water Pump Controls (`P01`, `P02`, `P03`) & Temperature Measurement

For compatible AquaTemp / PHNIX controllers (`default` and `1442284873216843776`), the water circulation pump parameters are exposed as editable configuration entities:

| Entity Name (EN / PT-BR)                                         | Code  | Platform | Values / Range                     | Description                                                                                                                                                                     |
| ---------------------------------------------------------------- | ----- | -------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Water pump mode [P01] / Modo da bomba de água [P01]              | `P01` | select   | `continuous` (`0`), `with_compressor` (`1`), `intermittent` (`2`) | Controls when the heat pump's own circulation pump (`TO PUMP` / `OUT2`) runs while the unit is powered on: **`0` (Continuous)** runs continuously whenever the heat pump is ON (even when target temperature is already met); **`1` (With compressor)** runs only together with the compressor (plus post-run delay); **`2` (Intermittent)** stops the pump once target temperature is reached and cycles it on periodically according to `P02` and `P03`. |
| Water pump interval [P02] / Intervalo da bomba de água [P02]     | `P02` | number   | `30 – 120 min` (step `1`)          | Pause interval between circulation cycles when `P01` is set to **Intermittent (`2`)** and the target temperature has already been reached.                                      |
| Water pump duration [P03] / Duração da bomba de água [P03]       | `P03` | number   | `2 – 20 min` (step `1`)            | Pump run duration during each intermittent sampling cycle (`P01 = 2`), and also the circulation duration used by the **Measure temperature** button.                            |

#### How the **Measure temperature** button works

When the heat pump is off/idle, the water sitting inside its heat exchanger cools down or warms up to ambient air temperature, making the inlet temperature sensor (`T2`) stale. Pressing **Measure temperature** circulates fresh pool water through the heat pump **without starting the compressor**:

1. Persists the current `P01` mode and target temperature to Home Assistant storage (`.storage/aqua_temp.config.json`) for crash/power-loss recovery.
2. Temporarily switches `P01` to **Continuous (`0`)** (if not already `0`) so the circulation pump starts immediately even when water temperature is above the setpoint.
3. Lowers the target temperature to the heat pump's minimum (`R10`, e.g. `15 °C`) **before** powering on in `heat` mode, keeping the compressor off.
4. Waits for the duration configured in **Water pump duration [P03]** (default fallback `5 min` on models without `P03`) and refreshes all sensors so the inlet temperature reflects the real pool temperature.
5. Turns the heat pump **OFF first**, then restores the original target temperature and original `P01` mode (clearing the recovery flag).
6. If Home Assistant restarts/crashes or the heat pump goes offline mid-cycle, the integration automatically restores `P01` (and turns off / restores the original setpoint if still stuck at minimum) on startup or as soon as the device comes back online. If you manually raise the target temperature mid-cycle, your heating request is respected and only `P01` is restored.

## Troubleshooting

### Logs

Before opening an issue, please provide logs related to the issue,
For debug log level, please add the following to your config.yaml

```yaml
logger:
  default: warning
  logs:
    custom_components.aqua_temp: debug
```

Or use the HA capability in device page:
Settings -> Devices & Services -> Aqua Temp -> 3 dots menu -> Enable debug logging
When done and would like to extract the log:
Settings -> Devices & Services -> Aqua Temp -> 3 dots menu -> Disable debug logging

Please attach also diagnostic details of the integration, available in:
Settings -> Devices & Services -> Aqua Temp -> 3 dots menu -> Download diagnostics

### Data from mobile app

If mapping for your device are incorrect, please follow the steps below before reporting an issue:

1. Install on your mobile device packet sniffer (I'm using for Android - NetCapture)
2. Activate the packet sniffer just for the app
3. Open the app
4. Login
5. Open relevant device
6. Open menu
7. Click on `Parameter Settings`
8. First cycle, use password for user parameters, code: `022`
9. Take screenshot of each screen (letter)
10. Repeat steps 8 & 9 with code `066` - factory parameters
11. Open packet sniffer app and extract requests (and responses) of `login`, `deviceList`, `getDataByCode`

Attach the following details to issue:

- Mobile App name and version
- Attach screenshots and logs as zip file or link for download
- Attach diagnostic details from HA integration

### Invalid Token

In case you have referenced to that section, something went wrong with the encryption key,
Encryption key should be located in `.storage/aqua_temp.config.json` file under `data.key` property,
below are the steps to solve that issue.

#### File not exists or File exists, data.key is not

Please report as issue

#### File exists, data.key is available

Example:

```json
{
  "version": 1,
  "minor_version": 1,
  "key": "aqua_temp.config.json",
  "data": {
    "key": "ox-qQsAiHb67Kz3ypxY19uU2_YwVcSjvdbaBVHZJQFY="
  }
}
```

OR

```json
{
  "version": 1,
  "minor_version": 1,
  "key": "aqua_temp.config.json",
  "data": {
    "key": "ox-qQsAiHb67Kz3ypxY19uU2_YwVcSjvdbaBVHZJQFY="
  }
}
```

1. Remove the integration
2. Delete the file
3. Restart HA
4. Try to re-add the integration
5. If still happens - report as issue

#### File exists, key is available under one of the entry configurations

Example:

```json
{
  "version": 1,
  "minor_version": 1,
  "key": "aqua_temp.config.json",
  "data": {
    "b8fa11c50331d2647b8aa7e37935efeb": {
      "key": "ox-qQsAiHb67Kz3ypxY19uU2_YwVcSjvdbaBVHZJQFY="
    }
  }
}
```

1. Move the `key` to the root of the JSON
2. Restart HA
3. Try to re-add the integration
4. If still happens - follow instructions of section #1 (_i._)
